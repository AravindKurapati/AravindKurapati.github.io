<p><em>This is a companion piece to “What I learned by tracking 4 frontier system prompts.” Read that first for methodology context.</em></p><figure><img loading="lazy" alt="" src="/writing/what-claudes-system-prompt-might-look-like-in-april/159c7ff55f08.png" /></figure><h3>The Data (N=3)</h3><p>I have three disclosed Claude system prompt versions in the corpus:</p><p>Anthropic/claude-sonnet-4.6.md: 5,348</p><p>Anthropic/claude-opus-4.6.md: 4,566</p><p>Anthropic/claude-opus-4.7.md: 3,903</p><p>Before making any predictions, the most important thing the data shows is that <strong><strong>opus 4.7 is shorter than opus 4.6</strong></strong> by about 15%. This is not what you’d expect if the working assumption is “system prompts only grow.”</p><p>They can shrink. Sonnet-4.6 is the longest of the three, which makes sense: a general-use model running across more product surfaces needs more instructions than a focused opus-class deployment.</p><p>The chain is short. Three data points are enough to spot structure but not enough to fit a trend with confidence.</p><h3>Six Predictions for April 2027</h3><h3>1. Wellbeing protocol will have versioning or expanded case coverage</h3><p><strong><strong>Confidence: High</strong></strong></p><p>The &lt;user_wellbeing&gt; block in opus 4.7 is already detailed…..it covers self-harm, disordered eating, addiction, mania, psychosis, dissociation and suicidal ideation as distinct cases.</p><p>It explicitly prohibits naming specific methods even in “means restriction” safety planning contexts. The next version likely adds at least one new case or splits the block.</p><p>Candidate additions: eating disorder recovery protocols distinct from general wellbeing advice; gambling and financial harm behaviors (currently absent); caregiver distress (someone asking on behalf of a family member in crisis).</p><p><strong><strong>Falsified if:</strong></strong> the &lt;user_wellbeing&gt; block is unchanged in wording and scope.</p><h3>2. A named &lt;lexical_constraints&gt; block</h3><p><strong><strong>Confidence: Medium-High</strong></strong></p><p>OpenAI’s GPT-5.1 personality variants have explicit word-ban lists ….“absolutely,” “certainly,” “of course” appear as banned filler in the “candid” personality. Claude opus 4.7 does not have an equivalent explicit list; word avoidances are implicit.</p><p>Given that OpenAI has already formalized this and that Anthropic is observably borrowing structural ideas (XML blocks, explicit protocols), expect a named &lt;lexical_constraints&gt; or &lt;communication_style&gt; section that enumerates specific words and phrases to avoid.</p><p><strong><strong>Falsified if:</strong></strong> no such explicit block appears, and lexical guidance remains scattered in persona prose.</p><h3>3. Search routing becomes per-topic rather than a single blanket rule</h3><p><strong><strong>Confidence: Medium</strong></strong></p><p>Currently: “if information may have changed since the knowledge cutoff, search.” (claude-opus-4.7.md:1127)</p><p>This is a single rule. In practice, the categories of “may have changed” are very different: financial prices (always stale within hours), scientific consensus (rarely stale within years), election results (stale on a specific known date), software versions (stale on every release).</p><p>A blanket rule produces both over-search (historical facts) and under-search (fast-moving topics).</p><p>Expect per-topic routing: a list of categories with explicit search policies (always / on-request / never), analogous to how the current prompt already special-cases “time-sensitive events that may have changed since the knowledge cutoff.”</p><p><strong><strong>Falsified if:</strong></strong> routing remains a single blanket rule with no categorical distinctions.</p><h3>4. Anti-sycophancy gets its own named block</h3><p><strong><strong>Confidence: High</strong></strong></p><p>Right now, anti-sycophancy guidance is scattered across persona sections: “maintain self-respect” (claude-opus-4.7.md:168), “avoid collapsing into self-abasement” (same section), the overall framing around honest pushback.</p><p>Given the industry-wide convergence on this as a named concern (Anthropic has written publicly about sycophancy as a failure mode; Grok has explicit anti-sycophancy rules at xAI/grok-4.2.md:23), expect Anthropic to formalize this into a named block with enumerated failure modes: capitulation under correction, excessive agreement and apology as avoidance.</p><p><strong><strong>Falsified if:</strong></strong> sycophancy guidance remains distributed across persona prose with no named section.</p><h3>5. Prompt length stays within ±20% of today’s 3,903 lines</h3><p><strong><strong>Confidence: Medium</strong></strong></p><p>The opus 4.7 shrink was intentional restructuring…..converting prose instructions into XML blocks. This consolidation pattern does not suggest a trend toward minimalism; it suggests a trend toward denser, more machine-readable structure. More XML means more can be said in fewer lines.</p><p>I expect further consolidation (net length roughly flat to slightly shorter) rather than either radical growth or radical shrinkage.</p><p><strong><strong>Falsified if:</strong></strong> the prompt exceeds ~4,700 lines (20% above current) OR drops below ~3,100 lines (20% below).</p><h3>6. Memory/user-model section expands and adds explicit policies</h3><p><strong><strong>Confidence: Medium-High</strong></strong></p><p>Claude already stores user memories and has guidance about when not to reference them (claude-opus-4.7.md:207, claude-opus-4.7.md:217). The current guidance is mostly prohibitive……don’t bring up sensitive memories unprompted, don’t label stored data as “the user’s profile.” It does not yet specify how memories should be actively used.</p><p>Expect the next version to add policies on the other side: when to proactively use stored context (vs. waiting to be asked), how to handle conflicting memories, how to handle a user who explicitly asks Claude to forget something.</p><p><strong><strong>Falsified if:</strong></strong> the memory section shrinks, is removed, or has no new active-use policies.</p><h3>What Would Falsify Everything</h3><p>All six predictions share a single failure mode: Anthropic changes the system prompt’s fundamental architecture.</p><p>Two plausible moves that would break most predictions:</p><p><strong><strong>Learned behavior replaces explicit instruction.</strong></strong> If Anthropic moves more behavioral constraints into RLHF rather than system prompts, the prompt could shrink dramatically and the predictions about named blocks would all be wrong. The prompt would become a thin routing layer.</p><p><strong><strong>Multi-agent orchestration fragments the prompt.</strong></strong> If Claude 5.x runs as an orchestrator over specialized sub-models….a safety model, a tool-use model, a persona model….each sub-model might have a minimal prompt, and the monolithic 3,900-line structure would not apply. The predictions are implicitly about a monolithic architecture continuing.</p><p>Both of these are plausible. Neither has been signaled. I consider them unlikely but non-negligible.</p><h3>Check Back April 2027</h3><p>If these predictions are right, the &lt;user_wellbeing&gt; block will have expanded, there will be a named anti-sycophancy section, and the prompt will be 3,500–4,700 lines with more XML structure and less prose. If I’m wrong, open an issue on the repo.</p><p>The dashboard is at <a href="https://aravindkurapati.github.io/ai-prompt-watch">https://aravindkurapati.github.io/ai-prompt-watch</a></p>
